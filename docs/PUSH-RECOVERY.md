# 主动消息未到达时

1. 先区分“请求已入队”“接收方运行中”“正文实际到达本聊天”和“双方闭环”。保存派发时返回的 taskId、目标会话和明确回信 thread UUID，不能拿工具成功代替收到报告。
2. 需要排查时调用 deepseek_status / bridge_status，仅检查服务版本、认证连接、会话是否运行及路由归属。不要调用会话正文、报告文件、日志或旧 result 接口来取得尚未推送的回报。诊断日志只允许提取连接错误等元数据，不读取 agent 正文。
3. 运行中继续等待主动消息。一次观察超时不等于停止，也不是重启、换任务或重新发送的理由。不设自动正文轮询，不用文件存在或更新时间推断结果。
4. 推送调用失败由发送方保留原目标及相同 requestId；确定失败按服务指示重试，结果不确定先核对传输状态，不能生成新 requestId 重复发送。只在连接状态变化、明确失败或用户要求时重查状态，避免循环查询。
5. 服务不可用时核对实际已安装版本、endpoint 配置与 token 文件可读性，不打印 token。缺少真实回信 UUID 就先解决身份缺失，不猜最新聊天。宿主确需重载时先确认没有运行中的工作并保护当前会话；不能用终止宿主来解决普通等待。
6. 状态仍无法解释时如实报告“尚未收到主动消息”及已有错误，保留任务和旧版本，等待可操作的环境变化或用户处理。不得改读 DeepSeek 报告补齐结果，不得虚假 complete/confirm 解锁归档。

只有已验证的同修订双方验收闭环允许定向读取该任务归档；单次 turn done 和旧接口释放绑定都不算闭环。replyRequired=false 通知不回执。

新客户端首先检查health.readPolicy；不支持push-only-until-closed的旧服务返回bridge/upgrade-required，且不调用任务结果或v2任务端点。请升级服务，不把客户端二次过滤当成允许从旧服务拉取正文。
